# 多 AI 协作工作区（Multi-Agent Workspace）

> 一个人 + 多个 AI 一起做同一个项目时，最贵的不是模型费用，而是**上下文丢失**和**互相覆盖**。
> 这个仓库是我在真实项目里跑出来的解法：用「约定 + 可跑的脚手架 + 任务台账」，让 Claude / DeepSeek / Codex 这些不同的 Agent 能在同一份文档上接力，而不是互相踩。

## 这是什么

一套可直接抄走的工作区骨架，包含三件事：

| 能力 | 解决什么 | 在哪 |
|---|---|---|
| **协作约定** | 多个 AI 同时改一个文件夹时，谁负责哪个目录、能不能改、改完怎么交付 | [`AGENTS.md`](AGENTS.md) |
| **多 Agent 编排脚手架** | 把「路由 → 专业 Agent → 审核 → 预算熔断」跑通，零第三方依赖 | [`04_多Agent系统/agentflow`](04_多Agent系统/agentflow) |
| **任务台账** | 跨会话记录「谁在做、做到哪、什么时候建的」，避免每次开会话都从零解释 | [`工具/ledger.py`](工具/ledger.py) |

## 可以直接跑的两段代码

### 1. 多 Agent 编排（零依赖，mock 模式）

```bash
cd 04_多Agent系统/agentflow
python main.py --mock "帮我看下本周商家数据，给一条运营建议"
```

输出是一条完整链路：`supervisor` 路由 → `analyst` → `merchant_ops` → `compliance` 审核，带步数 / token / 成本统计。去掉 `--mock` 并配 `DEEPSEEK_API_KEY` 就走真实模型（OpenAI 兼容接口）。

设计要点写在 [`多Agent协同设计.md`](04_多Agent系统/多Agent协同设计.md)：什么时候该上多 Agent、五种编排模式怎么选、怎么控上下文成本、失败兜底表。

### 2. 任务台账 CLI

```bash
python 工具/ledger.py list --mine
python 工具/ledger.py show --id <任务号> --json
```

任务与进展落成静态 Markdown，每个任务一个过程文档；`new / claim / log / close` 全程留痕。配套的踩坑记录见 [`工具/蓝鲸台账修复说明.md`](工具/蓝鲸台账修复说明.md)（Windows 应用白名单拦截未签名二进制、插件注册缺字段这类真实故障）。

## 怎么接到多 Agent 平台

这套骨架本身是「协议无关」的：约定和台账不依赖任何厂商。我在实际使用中把它接到 **Multica**（云端记工单 + 本机执行）上，本机跑 DeepSeek Harness 和 CodeBuddy 两个 CLI 运行时：

```
Multica（issue / 评论 / 运行记录）
        │  派单
        ▼
本机 daemon ──► dsh（DeepSeek Harness）──► 直接读写本项目目录
             └─► codebuddy ─────────────► 同上
```

关键在于两点：

1. **项目目录挂成 `local_directory` 资源**，Agent 就在你真实的项目目录里干活，而不是在空的临时目录里自说自话。
2. **写权限靠约定收窄**（见 `AGENTS.md` 的目录所有权表），而不是靠给 Agent 全盘权限。

## 这套约定的几条硬规则

- **不覆盖，只追加或新建带日期的副本**：删改别人的文件视为破坏
- **数字必须带口径**：金额写清「元/月」还是「元/年」、含不含税、哪一档实例
- **结论先行**：每份文档开头 3 行内给结论和推荐动作
- **区分事实 / 估算 / 建议**：估算标 `【估算】`，法规标 `【法规】` 并给来源链接
- **代码必须可运行**：附运行命令，依赖尽量为零
